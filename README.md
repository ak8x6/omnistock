# OmniStock — C Inventory Management Engine

> A terminal-based warehouse management simulator built in pure C, designed to practically apply core Computer Science data structures and algorithms in a real-world context.

---


## Features

| Feature | Description |
|---|---|
| **Product Catalog** | Add products with ID, name, price, and stock quantity |
| **BST Inventory View** | Display all products sorted by ID via in-order BST traversal |
| **Order Queue** | Queue restock/sale orders using FIFO processing |
| **Order Processing** | Dequeue and apply orders to live inventory data |
| **Undo System** | Reverse the last processed order using a LIFO stack |
| **Price Sorted View** | Extract BST data into an array and apply Quicksort by price |
| **Memory Safe** | All heap-allocated structures are explicitly freed on exit |

## Architecture & Data Structure Rationale

The system is composed of three independent modules, each backed by a deliberate data structure choice:

```
┌─────────────────────────────────────────────────────────────────────┐
│                         OmniStock Engine                            │
│                                                                     │
│   ┌──────────────────┐   ┌──────────────────┐   ┌───────────────┐  │
│   │  InventoryTree   │   │   OrderQueue     │   │  UndoStack    │  │
│   │  (BST)           │   │   (Linked Queue) │   │  (LIFO Stack) │  │
│   │                  │   │                  │   │               │  │
│   │  O(log n) lookup │   │  FIFO processing │   │  O(1) undo    │  │
│   │  O(n) in-order   │   │  of pending jobs │   │  of last op   │  │
│   └──────────────────┘   └──────────────────┘   └───────────────┘  │
│                                │                                    │
│                     ┌──────────┘                                    │
│                     ▼                                               │
│              Quicksort (price view)                                 │
│              Extracts BST → array → sorts in O(n log n)            │
└─────────────────────────────────────────────────────────────────────┘
```

### Why a BST for the inventory?
Products are identified by a numeric ID, making a BST the ideal structure. Insertion maintains sorted order automatically, and in-order traversal produces a perfectly sorted product listing — no extra sort pass needed.

### Why a Queue for orders?
Orders must be processed in the sequence they were received. A singly-linked FIFO queue models this naturally, ensuring fairness and auditability of stock changes.

### Why a Stack for undo?
Only the most recent operation ever needs to be reversed, making a LIFO stack the perfect fit. Each processed order is pushed onto the stack; undoing pops it and applies the inverse delta.

### Why Quicksort for price display?
The BST is ordered by ID, not price. To display inventory by price, nodes are extracted into a flat array via in-order traversal, then sorted using Quicksort — giving average O(n log n) performance with O(1) extra space per partition call.

```

│   ├── core_types.h         # Product & Order struct definitions
```

## Build & Run

**Prerequisites:** GCC and GNU Make.

```bash
# Clone the repository
git clone https://github.com/ak8x6/OmniStock-C-Inventory-Engine.git
cd OmniStock-C-Inventory-Engine

# Compile all sources
make

# Run the engine
./bin/OmniStock.exe          # Windows
# or
./bin/OmniStock              # Linux/macOS (rename target in Makefile)

# Clean build artifacts
make clean
```

### Compiler Flags Used

| Flag | Purpose |
|---|---|
| `-Wall -Wextra` | Enable all warnings — zero warnings in production |
| `-std=c99` | Strict C99 compliance |
| `-Iinclude` | Resolve header paths cleanly without relative `../` hacks |

## CLI Reference

```
=== OmniStock Menu ===
1. Add Product          → Insert a new product into the BST
2. Display (ID)         → Print inventory sorted by product ID (in-order traversal)
3. Add Order            → Queue a stock change (restock = positive, sale = negative)
4. Process Order        → Dequeue the next order and apply it to inventory
5. Undo                 → Reverse the last processed order (pop from stack)
6. Display (Price)      → Flatten BST + Quicksort → display inventory by price
7. Exit                 → Free all heap memory and quit
```

## Technical Highlights

- **Zero external dependencies** — built entirely on the C standard library.
- **Modular design** — each data structure is a fully isolated compilation unit with a clean header interface.
- **No memory leaks** — `destroy_tree()`, `destroy_queue()`, and `destroy_stack()` cleanly traverse and free all heap-allocated nodes on exit.
- **Makefile with pattern rules** — compiles each `.c` to a `.o` independently, enabling efficient incremental builds.
